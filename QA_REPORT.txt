PlantCare AI — QA and Fix Report

Competition patch summary
1. Fixed a false-rejection risk in the offline plant-presence fallback: it now accepts multiple plant-like patterns, including green foliage, flower-heavy yellow/red images, and mixed foliage/flower images. Color is used only for plant-presence screening, never to name a species.
2. Relaxed the photo-quality minimum slightly so usable close-ups are less likely to be rejected prematurely.
3. Made text/document rejection more conservative. A high local document score alone no longer rejects an image; stronger text-vs-plant model evidence is required. The independent general-object screen remains in place to reject obvious cars and other non-plant objects when its model is available.
4. Removed the spoken Home-page introduction entirely. Written creator credits elsewhere remain unchanged.
5. Added Plant Look-Alike Showdown: a single-session comparison of the top model candidates using the plant library's stored leaf, flower, growth and identification descriptions. These descriptions are explicitly labelled as reference traits, not proof that each trait was seen in the uploaded image.
6. Updated README to match the current build.

Checks performed on this package
- Python syntax compilation: passed.
- AST parsing: passed.
- plant_data.json: parsed successfully; plant records checked for common names and expected structure.
- Static checks: spoken introduction widget removed; Plant Look-Alike Showdown present; fallback and rejection threshold edits present.
- ZIP integrity: checked after packaging.

Not verified in this environment
- A live Streamlit browser session was not launched here.
- The BioCLIP and MobileNet model downloads/inference were not run end-to-end in this check.
- No guarantee is made that every plant image will be identified correctly. The specific car, marigold and tulsi images should be tested on the deployed app before the competition.
- A single photo cannot establish a definitive disease diagnosis or directly measure soil moisture, nutrient levels, root health or sunlight exposure.

Competition test checklist
- Test a clear car photo: it should be rejected as non-plant.
- Test a clear marigold photo: it should proceed to plant matching rather than be rejected only because the photo is flower-heavy.
- Test a clear tulsi photo: it should proceed to plant matching.
- Test one non-plant object and one blurry/dark plant photo.
- If model loading fails, check the visible error and use only the explicitly labelled fallback; do not claim full AI identification when BioCLIP is unavailable.

Conclusion
This patch reduces known false-rejection risks and adds a one-session look-alike comparison. It is statically checked, but it is not certified perfect; deploy and run the listed photo tests before the live judging session.
