PlantCare AI — audit and repair report (2026-10-18)

Input inspected: PlantCareAI-main (1).zip uploaded in this conversation.

Confirmed in source:
- plant_data.json contains 56 unique, complete profile records.
- Model hints exist for all 56 records.
- Identification uses BioCLIP 2 with original BioCLIP fallback, multi-prompt and multi-view image/text ranking.
- A MobileNetV3-Small ImageNet screen and BioCLIP text screens are used as non-plant safeguards when the weights are available.
- Health screening is a colour-mask heuristic, not a trained health classifier.
- The structured Copilot uses rules and plant profile information.

Repairs in this build:
- Removed the local colour/manual-clue fallback that could create unsupported species shortlists when the vision model failed. It now returns an explicit unavailable result instead of a species guess.
- Removed the numerical PlantCare Score because the underlying evidence cannot support a valid overall health/care score.
- Removed the percentage-style presentation of identification confidence; the UI explains that the category is a relative ranking signal, not a calibrated probability.
- Added a chat-style profile-grounded Copilot that does not require a paid AI inference API.
- Updated Python dependency pins for a more consistent Python 3.11 environment, including NumPy 1.26.4 with the pinned PyTorch version.
- Removed the unused optional Pl@ntNet client and its tests from this no-paid-API build.
- Updated documentation to state limits and test commands accurately.

Local verification:
- Python syntax compilation passed.
- Lightweight unit tests passed (see terminal verification during build).
- ZIP archive integrity checked after packaging.

Not verified:
- Streamlit was not installed in the audit environment; no full browser/server smoke test was run.
- open_clip_torch was not installed; BioCLIP weights were not downloaded and live inference was not run.
- No independent labelled image set for the 56 classes was supplied; accuracy cannot be certified.
- The model checkpoints may exceed free-hosting memory, disk, network or startup limits.
- Car/non-plant rejection has not been validated on a held-out test set; safeguards are not infallible.

Required next validation after deployment:
1. Check Streamlit logs for dependency/model-loading errors.
2. Test camera and gallery with the same known plant photos.
3. Test cars, people, indoor objects, non-supported plants, text screenshots, blurred/dark photos.
4. Build a held-out, correctly labelled image set for all 56 classes and report per-class precision/recall, confusion matrix, and non-plant false-accept rate before making accuracy claims.
